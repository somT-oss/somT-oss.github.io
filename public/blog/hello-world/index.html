Hello World — Why I Built My Own Blog

This is the first post on this site, so it feels right to write about why the site exists.

The Medium Problem

I’ve been meaning to write publicly for a while. I had a Medium account, drafted a few things, never published them. The problem wasn’t lack of ideas — it was friction. Not the good kind of friction that makes you think harder, but the annoying kind: paywalls, clunky editors, engagement optimization, and the feeling that I was writing for the platform rather than for myself.

Owning the Stack

Building your own blog in 2024 is almost a cliché, but I think it still matters. When you publish on someone else’s platform:

  • They can change the rules
  • Your content is tied to their existence
  • The algorithm decides who sees what
  • You’re a product, not a publisher

Here, none of that applies. This is a static site. It’s just files. It’ll keep working long after the hot new publishing platform of the moment implodes.

The Setup

The stack is dead simple:

  • Hugo — generates HTML from Markdown files
  • Decap CMS — gives me a browser editor so I don’t have to write frontmatter by hand
  • GitHub Pages — free hosting

Writing a post means opening /admin, typing, and hitting publish. It commits to GitHub and the site rebuilds in about a minute. That’s it.

What I’ll Write About

Mostly things I’m working on or thinking about:

  • Cloud infrastructure and Kubernetes war stories
  • Backend architecture decisions and the tradeoffs nobody tells you about
  • The experience of trying to get better at this craft
  • Occasionally: things that have nothing to do with engineering

If any of that sounds interesting, welcome. If not, also welcome — maybe I’ll write something useful eventually.
